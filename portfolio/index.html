How I work

Understand. Build. Break. Fix. Ship.

I start from the real problem, pick the tool that fits it, test how it breaks, and stay with it until it runs in production. Here's what that looked like on real work.

01 / UNDERSTAND

Find the actual cost

For an e-commerce client, the problem wasn't "scrape some sites". It was 5–8 hours of manual price checks every week. That set the bar: the system had to run on a schedule, unattended.

02 / BUILD

Structure that fits the problem

Seven competitor sites meant seven different page layouts. I gave each site its own scraper module behind a master dispatcher, so adding a competitor means adding a module, not editing working code.

03 / BREAK & FIX

Plan for the failure

Sites change their markup without warning, so the scraper uses selector fallback chains instead of one brittle selector. At Paynamics, partner requests are validated against their contract before they touch a transaction.

04 / SHIP

Own it end to end

At FPD I owned the onboarding automation from start to finish: the Lambda functions, the least-privilege IAM roles they run under, and Cognito access control across the app.
